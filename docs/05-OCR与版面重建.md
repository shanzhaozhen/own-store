# 05 · OCR 与版面重建

需求原话：「拍照的图片需要转成文字文档并且排版」。重点是**并且排版** —— 交付的不是一堆文字，是一份能直接改的 Word。

## 引擎选择

本地 **RapidOCR 3.x**（`rapidocr` + `onnxruntime` CPU），PP-OCRv5 **mobile** 模型随包分发。

为什么不是 PaddleOCR：`paddlepaddle` 在 Python 3.14 上没有轮子，实测无法安装。详见 [ADR-002](decisions/ADR-002-OCR引擎选择.md)。

为什么用 mobile 而不是 server 模型：店铺机配置未知且预计较弱，mobile 模型约 15 MB、CPU 上单页一两秒，server 模型精度提升有限但慢好几倍。长辈等不起。

**模型文件随包走，不联网下载** —— 店铺网络不一定稳，首次使用不能卡在下载上。

## 输入用增强后的图，不是原始照片

```python
prepared = enhance.prepare_for_ocr(image)  # 透视校正 + 去阴影 + 灰度
result = ocr_engine(prepared)
```

透视校正让文字行变水平（检测框更准），去阴影让暗部文字不被吞掉。这一条前处理链和「照片变清楚再打印」共用，不重复实现。

注意：**送 OCR 的不要用二值化后的图**。过度二值化会吃掉笔画细节，反而降低识别率。用去阴影 + 对比拉伸后的灰度图。

## 版面重建：从坐标框到 Word

RapidOCR 给的是 `[(box, text, score)]`，box 是四点坐标。要还原成段落，做四步：

### 1. 行聚类

按每个框的 y 中心排序，相邻框的 y 中心差 < **中位字高 × 0.6** 就归为同一行。用中位数而不是均值，避免个别大标题把阈值带偏。

### 2. 行内拼接

同一行的框按 x 左边界排序拼接。中文之间不加空格；相邻框的水平间隙 > 一个字宽时补一个空格（可能是分栏或制表位）。

### 3. 段落切分

计算所有相邻行的行间距，取中位数作基准。行间距 > **中位行间距 × 1.8** 视为段落分界。

### 4. 标题与居中判定

一行同时满足这两条 → 判为标题/居中段：

- 行宽 < 页面宽度 × 60%
- 行的水平中心与页面中心的偏差 < 页面宽度 × 8%

再加一条辅助判据：字高明显大于中位字高（× 1.3 以上）→ 更可能是标题。

### 输出

`python-docx` 生成 `.docx`：

- **页面必须显式设成 A4（210×297mm）**。python-docx 自带的模板是美国 Letter（215.9×279.4mm），只设页边距是不够的 —— 店里只有 A4/A3，拿 Letter 的文档去打，Word 会自己缩放或者把版面挪位，和 PDF 那条路出来的尺寸也就不一致了。这条有断言守着（`tests/test_physical_size.py`），详见 [10-证件二合一](10-证件二合一.md) 里"物理尺寸一致"那一节。
- 正文：宋体 12pt（小四），行距 1.5，首行缩进 2 字符
- 标题：加粗、居中、稍大字号
- 页边距按常规公文习惯设

同时另存一份 `.txt`，方便长辈直接复制粘贴。

两个文件都落在 `%LOCALAPPDATA%\ShopPrint\output\`，界面上给一个大按钮「打开文件夹」。

## 识别不可能 100% 准

这一点要在界面上诚实告知，而不是假装完美：

- 结果页给一个可编辑的文本预览，长辈能直接改明显的错字再导出
- 低置信度的字（score < 0.7）在预览里标出来，提示「标红的字可能认错了，请核对」
- 文案上不说"转换完成"，说「已经转好了，请核对一下文字有没有认错」

## 云端高精度（v1 只留接口）

`core/ocr_cloud.py` 定义协议：

```python
class CloudOcrProvider(Protocol):
    name: str

    def recognize(self, image: np.ndarray) -> str:
        """返回 Markdown 文本（标题、列表、表格）"""
```

再配一个 Markdown → docx 的转换器（标题层级、列表、表格）。

为什么云端返回 Markdown 而不是坐标框：视觉大模型 / 带版面分析的云 OCR 本身就擅长直接输出结构化文本，表格和多栏排版的还原质量远超本地坐标聚类。走 Markdown 中间格式，换 provider 不用改下游。

v1 界面上「高精度识别」按钮**置灰**，提示「还没设置」。在 `config.json` 里填好 provider 和 key 后自动启用。

什么时候需要它：表格、多栏排版、复杂公文。本地聚类对付这些吃力。

## 性能预期

开发机（i9-9900K）单页 A4 预计 1–2 秒。店铺机配置未知，可能 3–8 秒。所以：

- 必须跑在工作线程，界面显示大进度提示「正在识别，请稍等…」
- 多页时逐页出结果，不要等全部完成才显示
