# 04 · 文档转换与打印

## 归一化：一切 → PDF

打印路径只有一条，所以先把所有格式统一成 PDF。转换结果按**源文件内容 hash** 缓存到 `%LOCALAPPDATA%\ShopPrint\cache\`，同一份文件重复打印不重复转换。

| 输入 | 怎么转 | 注意 |
|---|---|---|
| `.pdf` | 原样通过 | 先用 PyMuPDF 打开校验；加密的给友好提示「这个文件有密码，打不开」 |
| `.jpg .jpeg .png .bmp .webp .tif` | 过 `enhance` → PyMuPDF 排到页面 | 支持"适应纸张 / 原尺寸 / 铺满"，多张合并成一份 PDF |
| `.doc .docx` | Word COM `ExportAsFixedFormat` | 子进程隔离 |
| `.xls .xlsx` | Excel COM `ExportAsFixedFormat` | **必须先设"一页宽"**，见下 |
| `.txt` | PyMuPDF 自己排版 | 内嵌中文字体，不依赖系统装了什么 |
| `.ppt .pptx` | PowerPoint COM | v1 可选；缺失时提示「这种文件暂时打不了」 |

## Office COM 的坑

### 1. Excel 宽表会被切成几十页

复印店最常见的浪费纸事故。Excel 默认按实际宽度分页，一张十几列的表能横着切成 5 页、竖着切成 8 页 = 40 张纸。

导出前必须设：

```python
ws.PageSetup.Zoom = False  # 必须先关 Zoom，否则 FitToPages 无效
ws.PageSetup.FitToPagesWide = 1  # 横向压成一页宽
ws.PageSetup.FitToPagesTall = False  # 纵向不限，该多少页就多少页
```

`Zoom = False` 这一步顺序不能颠倒 —— Zoom 和 FitToPages 互斥，Zoom 开着时 FitToPages 会被忽略。

列特别多时还要考虑自动改横向：

```python
if used_width_cm > used_height_cm:
    ws.PageSetup.Orientation = 2  # xlLandscape
```

### 2. Word / Excel 会崩，不能拖死主程序

COM 自动化调的是真的 Office 进程，遇到损坏文件、宏、缺字体时可能弹窗或卡死。所以**转换跑在独立子进程里**，主程序设 120 秒超时，超时就杀进程并提示「这个文件处理太久了，可能有问题」。

子进程怎么起（`core/convert.py: _worker_command`）：

```python
# 开发时
[sys.executable, "-m", "shop_print.core.office_worker", src, dst]
# 打包成 exe 之后没有 python -m，改成自己带标志重新执行一次
[sys.executable, "--office-worker", src, dst]
```

所以 `__main__.py` 里 `--office-worker` 这个分支必须**在建 QApplication 之前**处理掉，否则子进程会先起一个界面。子进程用 `CREATE_NO_WINDOW`，不闪黑框。

### 3. COM 的固定套路

```python
pythoncom.CoInitialize()  # 每个线程/进程都要
app = win32com.client.DispatchEx("Word.Application")  # DispatchEx 起独立实例，不抢用户正开着的 Word
app.Visible = False
app.DisplayAlerts = False
try:
    doc = app.Documents.Open(str(src), ReadOnly=True, AddToRecentFiles=False)
    doc.ExportAsFixedFormat(str(dst), 17)  # 17 = wdExportFormatPDF
finally:
    doc.Close(False)
    app.Quit()
    pythoncom.CoUninitialize()
```

`DispatchEx` 而不是 `Dispatch`：`Dispatch` 会复用已经打开的 Office 实例，万一长辈正在用 Word 编辑东西，我们的 `Quit()` 会把人家的窗口关掉。

路径一律传**绝对路径字符串**，COM 不认 `Path` 对象，也不认相对路径。

### 4. 备选方案：LibreOffice

店铺机已确认装了 Microsoft Office，所以 v1 走 COM。如果以后换机器没有 Office，退路是随包带 LibreOffice 便携版：

```
soffice.exe --headless --norestore --convert-to pdf --outdir <dir> <file>
```

代价是打包体积多约 400 MB，且版式还原不如 Office。所以只作为备选，不默认打包。

## 打印：PDF → 柯美 225i

### 为什么自己用 GDI 打，不调外部程序

见 [ADR-003](decisions/ADR-003-打印后端选择.md)。简单说：自己控制 DEVMODE 才能确保份数、双面、纸张、单色确实生效，而且不引入外部 exe 依赖。

### 实现

```python
# 1. 取并修改 DEVMODE
h = win32print.OpenPrinter(printer_name)
info = win32print.GetPrinter(h, 2)
dm = info["pDevMode"]
dm.Copies = copies
dm.Duplex = 2 if duplex else 1  # 2 = 长边翻转
dm.PaperSize = 9  # A4。**不要用 win32con.DMPAPER_A4**：某些 pywin32 版本没这个属性，
# 缺一个常量就整个模块导入失败，所以纸张代码在 printing.py 里显式写死
dm.Color = 1  # DMCOLOR_MONOCHROME —— 225i 只有黑白
dm.Fields |= DM_COPIES | DM_DUPLEX | DM_PAPERSIZE | DM_COLOR

# 2. 建打印 DC
dc = win32ui.CreateDC()
dc.CreatePrinterDC(printer_name)  # 或 CreateDC("WINSPOOL", name, dm)

# 3. 逐页光栅化 + 送图
for page in doc:
    pix = page.get_pixmap(dpi=300, colorspace=fitz.csGRAY)
    # 按可打印区域等比缩放居中，StretchDIBits 送出
```

### 关键细节

- **DPI 用 300**。600 dpi 下 A4 灰度图是 7016×9933 ≈ 70 MB/页，弱机器上会吃满内存；300 dpi 对黑白文字打印已经足够，一页约 17 MB。
- **可打印区域不等于纸张尺寸**。用 `dc.GetDeviceCaps(PHYSICALOFFSETX/Y)` 和 `HORZRES/VERTRES` 算出真实可打区域，等比缩放并居中，否则内容会被裁掉边。
- **方向自适应**：页面宽 > 高时把 `dm.Orientation` 设横向，避免宽页被压扁。
- **进度回调**：每页结束回调一次，界面显示「正在打印第 2 页 / 共 5 页」。
- **`StartDoc / StartPage / EndPage / EndDoc` 必须配对**，异常路径里也要 `AbortDoc`，否则打印队列里会留一个卡死的任务 —— 长辈遇到这个只能重启电脑。
- **双面能力查不到时不降级**。`DeviceCapabilities(..., DC_DUPLEX)` 在有些驱动上会抛一个它自己接住的 Windows 结构化异常（开发机虚拟打印机上实测 `0x80040155`）。所以 `duplex_support()` 返回三态：`True` / `False` / `None`（问不出来），只有明确 `False` 才改成单面。选了双面却出一堆单面纸，比让驱动自己决定更糟。
  这个查询也**只在真要双面时才做**，不在列打印机时顺手查一遍 —— 那样每次打开打印页都要挨个问一遍驱动，既慢又会刷一堆异常日志。
- **虚拟打印机要能静默输出**。`PrintSettings.output_file` 会走 `StartDoc(job, 输出路径)`，「Microsoft Print to PDF」就不弹"另存为"了。开发机上的端到端测试全靠这个（`tests/test_printing.py`）。
- **证件复印不许缩**。默认路径是"整页等比缩放到可打印区"，而真打印机四周有 4–5mm 打不到的边 —— 缩放比例约 0.96，85.6mm 的身份证就打成 82mm。`PrintSettings.actual_size=True` 改走 `_draw_actual_size()`：按 `页面pt/72 × 打印机DPI` 算像素、画在 `(-PHYSICALOFFSET)` 处，让页面的 1mm 正好落在纸的 1mm 上。超出可打印区的部分由驱动裁掉（证件排版留了 6mm 安全边）。普通文档保持默认的"缩到可打印区"，宁可整体小一点也不裁掉边上的内容。详见 [10-证件二合一](10-证件二合一.md)。

### 备选后端（配置项 `print_backend`）

`gdi`（默认）| `sumatra`。如果柯美驱动在 GDI 路径上表现异常（页边距不对、双面失效等），改用随包的 SumatraPDF 便携版：

```
SumatraPDF.exe -print-to "<打印机名>" -print-settings "1-5,duplex,2x" -silent -exit-when-done <file.pdf>
```

优点是驱动兼容性极好、久经考验；缺点是多一个外部 exe（GPLv3），且拿不到细粒度进度。v1 默认 GDI、不打包 Sumatra，出问题再切。

## 打印预览：画出"纸上会是什么样"

`printing.preview_sheet()` 返回一张 PNG（core 不许 import Qt，所以给字节）：白纸 + 纸边 + 可打印区虚线 + 按真打印算式摆好的内容。

**和"预览 PDF 页面"不是一回事**：那种预览只告诉你内容长什么样，答不了"会不会被缩"、"边上会不会裁掉"。所以这一张刻意和真打印共用同一套摆放算式（`_actual_size_rect()` / 等比居中），预览要是"另一套逻辑画出来的好看图"，反而误导人。

纸张和边距靠 `paper_metrics()` 问驱动（`PHYSICALWIDTH/HEIGHT`、`HORZRES/VERTRES`、`PHYSICALOFFSETX/Y`）。问不出来时按"整张纸都能打"返回并把 `measured` 标成 False，界面上说明"页边距问不出来" —— 宁可乐观一点，也不要因为拿不到边距就不给预览。

界面上打印机就摆在这一页选（不藏进设置里）：店里可能同时有柯美和虚拟打印机，长辈要能自己选，而且得看得见现在往哪台机器打。换打印机或换纸张都会重画预览 —— 页边距和缩放都可能跟着变。
