## 柯美 bizhub 225i

已知（来自用户）：**只能黑白打印**。所以界面上一切彩色选项直接禁用并写明原因，`DEVMODE` 里显式设单色。

待现场确认并回填到本文档：

- 打印机在系统里的**准确名称**（`Get-Printer | Select Name`）—— 配置默认值要用它
- 驱动类型（PCL / PS / KONICA MINOLTA 通用驱动）
- 支持的纸张（A4 / A3 / B5）与默认纸张
- 是否支持自动双面（有无双面器选件）
- 分辨率（一般 600 dpi）—— 决定光栅化 DPI，目前代码里按 300 dpi 渲染

`scripts\采集店铺环境.bat` 会把上面前四项直接读出来（含 `Get-PrintConfiguration` 的 `DuplexingMode`）。

**双面能力查询在开发机上是查不准的**：`win32print.DeviceCapabilities(..., DC_DUPLEX)` 在虚拟打印机上会抛一个驱动自己接住的 Windows 结构化异常（实测 `0x80040155`）。所以代码里问不出结果时**按用户选的来**，不擅自降级成单面 —— 见 `core/printing.py` 的 `duplex_support()`。

## 微信收到的文件在哪

两代布局不一样，程序启动时**两种都探测**，存在哪种用哪种：

- **WeChat 3.x**：`%USERPROFILE%\Documents\WeChat Files\<wxid>\FileStorage\File\<yyyy-MM>\`
  （开发机实测：`wxid_ks1gjsurgdci22\FileStorage` 存在）
- **WeChat 4.x**：`%USERPROFILE%\Documents\xwechat_files\<wxid_hash>\msg\file\<yyyy-MM>\`
  （开发机上不存在，路径依据 4.x 通行布局，需在店铺机核实）

**版本号不能用来推断目录布局**（2026-08-16 实测）：开发机装的是 4.1.11.24，按"4.x 用 xwechat_files"的说法应该有 `xwechat_files`，实际只有 3.x 的 `WeChat Files`（大概是从 3.x 升级上来、数据目录没迁）。所以代码里**不去判版本，两种布局一起探测**，`detect_wechat_dirs()` 就是这么写的。

用户可以在微信里改接收目录。注册表 `HKCU\Software\Tencent\WeChat` / `...\Weixin` 下的 `FileSavePath`（值为 `MyDocument:` 表示还是默认文档目录）记着这个设置，`scripts\collect-shop-env.ps1` 会一并读出来 —— 店铺机万一改到了 D 盘，靠这个才能发现。配置里 `intake.wechat_dirs` 手填的目录优先于自动探测。

**注意：聊天里的「图片」和「文件」不是一回事。**以`文件`形式发来的 pdf/doc/xls/jpg 会原样落在上面的 `File` 目录，可以直接监控。而聊天里直接发的**图片存在 `Image` 目录且是加密的 `.dat`**，不做解密。

所以图片的接入路径是另外三条：

1. 长辈在微信里「另存为」到桌面的 `待打印` 文件夹（`C:\打印\待打印`，安装时创建 + 桌面快捷方式）
2. 在微信里右键「复制」图片，回到工具点「粘贴图片」（`Ctrl+V`）—— **对长辈最省事**
3. 直接把文件拖进工具窗口

## Python 3.14 依赖可用性（已逐个探测）

有 cp314 轮子，可用：

`pillow 12.3.0`、`numpy 2.5.2`、`opencv-python-headless 4.14.0.94`（也有 5.0，但选 4.x 求 API 稳定）、`PySide6 6.11.1`、`rapidocr 3.9.2`、`onnxruntime 1.28.0`、`pywin32 312`、`PyMuPDF 1.28.2`、`python-docx 1.2.0`、`openpyxl 3.1.5`、`pypdf 6.16.1`、`watchdog 6.0.0`、`pyinstaller 6.22.1`、`pytest 9.1.1`、`ruff 0.16.3`、`fastapi` / `uvicorn` / `httpx` / `pydantic`（第二阶段用）

**不可用**：`paddlepaddle` —— `pip index versions paddlepaddle` 直接报 `No matching distribution found`，即 cp314 无轮子。因此 PaddleOCR 路线作废，详见 [ADR-002](decisions/ADR-002-OCR引擎选择.md)。

**踩坑预警**：必须用 `opencv-python-headless`。完整版 `opencv-python` 自带一套 Qt 库，和 PySide6 的 Qt 冲突，会在启动时崩溃或报 plugin 加载失败。
