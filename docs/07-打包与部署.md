# 07 · 打包与部署

店铺机不装 Python，只跑打包产物。目标是**一个文件夹拷过去、双击桌面图标就能用**。

## 开发环境

```powershell
cd C:\Project\own-store
.\scripts\setup-dev.ps1      # 建 venv + 装依赖 + 把 opencv 换回 headless
```

依赖版本全部钉死在 `pyproject.toml`；`requirements.lock` 是开发机上实际装出来的完整快照（连传递依赖），保证换机器能复现。重新生成：

```powershell
.\.venv\Scripts\python.exe -m pip freeze --exclude-editable
```

打包前还要准备两样随包资源（都不进 git，见 `.gitignore`）：

```powershell
.\scripts\prepare-models.ps1   # 把 RapidOCR 的 3 个 onnx（~30 MB）拷进 assets\models
python scripts\make_icon.py    # 生成 assets\icons\app.ico（脚本画的，不引入来源不明的素材）
```

## 打包

`scripts\build.ps1` 跑 PyInstaller，产物在 `dist\打印助手\`。

关键参数与理由：

| 参数 | 为什么 |
|---|---|
| `--onedir` | **不要 `--onefile`**。onefile 每次启动都要把 onnx 模型和 Qt 库解压到临时目录，弱机器上要等好几秒，长辈会以为卡死了然后连点好几下 |
| `--windowed` | 不弹黑色控制台窗口 |
| `--name 打印助手` | 中文名，长辈能认出来 |
| `--icon` | 有图标才像正经软件 |
| `--add-data assets;assets` | 图标、中文字体、OCR 模型都要带上。**目标路径要和 `paths.bundle_root()` 对上**：打包后是解包目录（`sys._MEIPASS`），所以是 `assets` 而不是 `shop_print/assets` |
| `--add-data style.qss;ui` | 同理，`paths.style_file()` 找的是 `bundle_root()/ui/style.qss` |
| `--collect-all rapidocr` | RapidOCR 的模型配置是数据文件，PyInstaller 静态分析找不到 |
| `--exclude-module PyQt5/PyQt6/PySide2/tkinter` | 避免误打进别的 GUI 框架，白占体积 |

**入口脚本是 `scripts\launcher.py`，不是 `src\shop_print\__main__.py`。**PyInstaller 会把入口当成 `__main__` 直接执行，而 `__main__.py` 用的是相对导入（`from . import config`），被当顶层脚本跑时没有包上下文，导入直接失败。`launcher.py` 只做一件事：以正常包导入的方式调 `shop_print.__main__:main`。

打包脚本还会在开跑前检查 `cv2` 目录里有没有 `qt\` —— 装成完整版 opencv 的话打完包才发现就太晚了。

体积预估：PySide6 + onnxruntime + OpenCV，约 300–450 MB。可接受 —— 拷一次就完事。

打完包必须**在打包环境之外**跑一次 `dist\打印助手\打印助手.exe`，确认不是靠开发机的虚拟环境才能起来；再跑一次「照片转文字」，确认 OCR 模型真的被打进去了。

### 自检：`打印助手.exe --self-check`

打包成 `--windowed` 之后出问题什么都看不见，而店铺机上没有 Python、也没人会看命令行。所以程序自带一条自检：

```powershell
.\dist\打印助手\打印助手.exe --self-check
```

它不开界面，逐项检查并把报告写到 `%LOCALAPPDATA%\ShopPrint\logs\自检报告.txt`（UTF-8，让父母把这个文件发回来就行），全通过时退出码为 0：

- 随包资源到位没有：OCR 模型（3 个 onnx，~30 MB）、`ui\style.qss`、`app.ico` —— **`--add-data` 路径写错是最常见的打包事故**
- 运行时目录（配置 / 记录 / 缓存 / 日志 / 输出）和 `C:\打印\待打印` 建得出来没有
- 打印机列表 + 默认打印机，并专门找名字带 `225` / `KONICA` 的那台，顺带报双面能力
- 中文能不能写进 PDF（txt 转 PDF 全靠内置中文字体）
- **OCR 在这台机器上跑一张要多久** —— 店铺机比开发机弱，超过 8 秒会额外提醒界面必须有进度条

开发机实测（2026-08-16，打包版）：窗口 1.5 秒出来，OCR 一张 2.9 秒，全部通过。

## 装到店铺机

双击 `scripts\安装到店铺电脑.bat`（真正的逻辑在 `scripts\install-to-shop.ps1`，bat 只是个 ASCII 外壳，避免 cmd 换代码页把中文变成乱码）。它做四件事：

1. 把 `打印助手\` 拷到 `C:\ShopPrint\`，**旧版本先改名成 `C:\ShopPrint.bak\` 留着**
2. 公共桌面创建快捷方式「打印助手」
3. 创建 `C:\打印\待打印\`，并在公共桌面放它的快捷方式
4. 加 `-AutoStart` 参数时写开机自启（不加就顺手清掉之前设过的）

用**公共桌面**（`%PUBLIC%\Desktop`）而不是当前用户桌面：装的时候可能是管理员账号，平时用的是另一个账号 —— 图标必须出现在长辈真正用的那个桌面上。脚本需要管理员权限（要写 `C:\` 根目录和公共桌面），会自己请求提权。

**桌面上只留两个图标**：「打印助手」和「待打印」。多一个都会让长辈犹豫。

## 去店铺之前先采集环境

双击 `scripts\采集店铺环境.bat`（逻辑在 `scripts\collect-shop-env.ps1`）—— 让父母或你自己在店铺机上跑一次，结果存到桌面「店铺环境」文件夹（`.txt` 给人看、`.json` 给代码用），整个文件夹发回来即可。只读，不改任何东西，不需要管理员。

导出内容：

- `Get-Printer` 全量输出（拿柯美 225i 的**准确名称**、驱动、端口、`DuplexingMode`）+ 默认打印机
- 微信版本、注册表里的 `FileSavePath`、以及**实际存在的接收目录**（3.x / 4.x 两种布局都探，还会数最近 7 天有多少文件）
- Windows 版本与构建号（PySide6 6.11 要求 ≥ 17763，脚本会直接告警）
- CPU / 内存（预估 OCR 耗时）、C 盘剩余空间
- Office / WPS 的安装路径与版本（**只有 WPS 没有 Office 的话转换要换一套接口**，脚本会告警）
- 屏幕分辨率与显示缩放（界面布局要适应；竖向 < 720 会告警）

拿到这些再定默认配置，比到现场手忙脚乱调好。

## Win10 兼容

- PySide6 6.11 要求 Win10 1809 以上。店铺机的具体版本号一并在采集脚本里读出来
- 在 Win11 上构建的 x64 产物可以在 Win10 x64 运行，但**必须在店铺机实测一次**才算交付
- 目标只有 x64，不做 32 位

## 升级与回滚

- 升级 = 覆盖 `C:\ShopPrint\` 里的文件（配置和记录在 `%LOCALAPPDATA%\ShopPrint\`，不会被覆盖）
- 回滚 = 把旧版文件夹换回来。所以**每次升级前把旧文件夹改名留着**，比如 `C:\ShopPrint.bak\`
- 不做自动更新。远程给长辈操作升级的风险大于收益

## 交付前的检查清单

在店铺机上逐项过：

- [ ] `打印助手.exe --self-check` 全部通过（这一条先做，能一次排掉资源没打进去、模型丢了、字体不行这几类问题，还能拿到这台机器的 OCR 耗时）
- [ ] 双击桌面图标能起来，不闪退，不弹控制台
- [ ] 柯美 225i 出现在打印机列表里且默认选中
- [ ] 拍照文档：增强后打出来背景干净、字清楚
- [ ] **证件二合一：身份证正反面打一张，用尺子量长边是不是 85.6mm**（真打印机四周吃 4–5mm，`actual_size` 那条路只能在这里验；量出来偏小就说明补偏移没生效）
- [ ] 户口本两页：应当自动换成横向 A4 并排，两页都是正着看的
- [ ] Word 文档：一键打印，版式正确
- [ ] **Excel 宽表：不会被切成几十页**
- [ ] 多页 PDF：页数、顺序、方向都对
- [ ] 双面打印（如果有双面器）
- [ ] 微信发个文件过来，首页 3 秒内出现
- [ ] 微信里复制图片，「粘贴图片」能拿到
- [ ] 照片转文字：docx 能打开、段落分得对
- [ ] 拔掉打印机线，提示是「请看看电源和数据线」而不是错误码
- [ ] **父母不看提示、不打电话，独立完成一次完整打印**

最后一条是真正的验收标准。卡住的地方就是要改的地方。
