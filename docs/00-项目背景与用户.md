# 00 · 项目背景与用户

## 店铺在做什么

父母经营一家小店，业务里包含打字复印打印。顾客拿着要打印的东西来，或者**用微信把文件发到店铺电脑上**，店里打出来收钱。

设备很简单：一台 Windows 10 台式机 + 一台柯美（Konica Minolta）bizhub 225i，**只能黑白打印**。

## 谁在操作

**父母，年纪比较大，不熟悉电脑。**这是整个项目最重要的约束。

具体意味着：

- 不认英文，看不懂"Error"、"Exception"、错误码
- 记不住多步流程，"文件 → 打印 → 属性 → 页面设置 → 缩放"这种路径学不会也记不住
- 屏幕上字太小看不清，按钮太小点不准
- 出现看不懂的提示会不敢往下点，直接叫人
- 学会一种做法之后不会主动换，所以**第一版教会的那条路必须是对的**

设计上的直接推论：

- 一屏放下所有功能，四张大卡片，图标 + 大字
- 每件事最多三次点击
- 任何提示都是人话，说清"要你做什么"，比如「打印机没有连上，请看看它的电源和数据线」
- 不给"高级设置"，参数由程序自动判断；确实要调的只留一个"淡 ←→ 浓"滑块

## 四个真实痛点（用户原话整理）

1. **拍照文档打印效果差** —— "打印的文件有时候是图片…图片打印经常是拍照出来的，打印的格式会有问题…拍照的文档，背景色有阴影之类的"。
   手机拍的纸质文档，画面里有手机/人的阴影、纸张本身发黄发灰。黑白激光机会把这些底色全部打成脏灰块，文字反而发虚。**要把背景弱化、内容变清楚。**

2. **办公文档打印虽然能用，但流程繁琐** —— "办公文档打印还好"。
   能打，但要在 Word/Excel/PDF 阅读器里各点一套设置。尤其 Excel 宽表格如果不设置"调整为一页宽"，会哗哗吐出几十张纸 —— 这是复印店最常见的浪费纸事故。

3. **拍照件要转成可编辑文档** —— "拍照的图片需要转成文字文档并且排版的功能"。
   不只是识别出文字，还要**排好版**（段落、标题、居中），交付的是能改的 Word。

4. **文件要先找得到** —— 顾客微信发过来，长辈得在微信里点开、另存为、再到文件夹里找。
   工具应该让新文件**自动出现在首页**。

## 版本规划

**v1（当前）** —— 桌面工具，四个功能：照片去底增强后打印、办公文档/PDF 一键打印、自动监控微信接收文件夹、照片转文字文档。

**v2** —— 微信小程序：顾客自己选文件 → 打印预览 → 确认没问题 → 支付 → 店里自动打印出来。见 [08-第二阶段-微信小程序](08-第二阶段-微信小程序.md)。

v1 的架构已为 v2 铺路：`core/` 不依赖 Qt（服务端可直接复用），打印记录从第一天就落 SQLite（收费统计的基础）。

## 衡量成功的标准

不是功能列表打勾，而是：**父母不看任何提示、不打电话问，能独立完成一次完整打印。**

验收时让他们自己操作一遍，卡住的地方就是要改的地方。
